# Enhanced Distributed Worker Service Implementation with Cosmos DB Change Feed Processor Patterns

## Project Overview
Create a .NET 8 Worker Service that processes changes from an external API using proven Azure Cosmos DB Change Feed Processor patterns for distributed, fault-tolerant coordination across multiple machines. The service will implement lease-based work distribution with automatic failover and dynamic scaling capabilities.

## Architecture Improvements Based on Cosmos DB Change Feed Processor

### Key Patterns Adopted
1. **Lease Container Pattern**: The lease container acts as state storage and coordinates the processing of the change feed across multiple workers
2. **Observer Pattern**: The change feed processor library follows the observer pattern, where your processing function is called by the library
3. **At-Least-Once Delivery**: The main benefit of using the change feed processor is its fault-tolerant design, which assures an "at-least-once" delivery of all the events in the change feed
4. **Dynamic Scaling**: The change feed processor can dynamically adjust a container's scale if the container's throughput or storage increases

## Core Requirements

### 1. Service Architecture
- **Base**: .NET 8 Worker Service with Change Feed Processor patterns
- **Pattern**: Distributed processing with lease-based coordination using proven Cosmos DB patterns
- **Storage**: Azure Cosmos DB with dedicated lease container and monitoring container
- **Authentication**: OAuth 2.0 for external API
- **Data Format**: JSON responses from external API
- **Error Handling**: Retry mechanism with "at-least-once" guarantee

### 2. External API Integration
The service integrates with an external API that has two endpoints:
- **Metadata Endpoint**: Returns list of tasks (key ranges) that need processing
- **GetChanges Endpoint**: Returns changes for a specific task/key range

### 3. Enhanced Distributed Coordination (Change Feed Processor Style)
- **Deployment Units**: Multiple worker instances with same processor name but different instance names
- **Lease Management**: Automatic lease acquisition, renewal, and release
- **Dynamic Load Balancing**: Automatic redistribution of work when instances join/leave
- **Fault Tolerance**: Automatic failover with lease expiration and recovery
- **Life Cycle Notifications**: Comprehensive monitoring of lease state changes

## Enhanced Components (Based on Change Feed Processor Architecture)

### 1. Main Worker Service (Host)
```csharp
public class ExternalApiChangeProcessorWorker : BackgroundService
{
    private readonly ExternalApiChangeProcessor _processor;
    private readonly ILogger<ExternalApiChangeProcessorWorker> _logger;

    // Implements the hosting pattern similar to Change Feed Processor
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        await _processor.StartAsync(stoppingToken);
        
        // Keep running until cancellation
        await Task.Delay(Timeout.Infinite, stoppingToken);
        
        await _processor.StopAsync();
    }
}
```

## Enhanced Processing Workflow

### 1. Processor Initialization
```csharp
// Builder pattern usage
var processor = ExternalApiChangeProcessor
    .Create("external-api-processor", HandleChangesAsync)
    .WithInstanceName(Environment.MachineName + "-" + Guid.NewGuid())
    .WithLeaseContainer(leaseContainer)
    .WithLeaseAcquireNotification(OnLeaseAcquiredAsync)
    .WithLeaseReleaseNotification(OnLeaseReleasedAsync)
    .WithErrorNotification(OnErrorAsync)
    .WithLeaseAcquireInterval(TimeSpan.FromSeconds(17))
    .WithLeaseExpirationTime(TimeSpan.FromSeconds(60))
    .WithLeaseRenewalInterval(TimeSpan.FromSeconds(13))
    .WithMaxDegreeOfParallelism(4)
    .WithPollInterval(TimeSpan.FromSeconds(5))
    .Build();

await processor.StartAsync();
```

### 2. Processing Life Cycle
1. **Lease Discovery**: Periodically scan for available leases (every 17 seconds by default)
2. **Lease Acquisition**: Attempt to acquire available leases using optimistic concurrency
3. **Processing Loop**: For each owned lease, continuously process changes
4. **Lease Renewal**: Renew owned leases every 13 seconds to maintain ownership
5. **Error Handling**: On errors, release lease and allow other instances to pick up
6. **Dynamic Scaling**: Automatically redistribute leases when instances join/leave

### 3. Change Processing Delegate
```csharp
private static async Task HandleChangesAsync(
    ExternalApiProcessorContext context,
    IReadOnlyCollection<ExternalApiChange> changes,
    CancellationToken cancellationToken)
{
    _logger.LogInformation($"Processing {changes.Count} changes for lease {context.LeaseToken}");
    
    foreach (var change in changes)
    {
        // Process individual change
        await ProcessChangeAsync(change, cancellationToken);
    }
    
    _logger.LogInformation($"Completed processing changes for lease {context.LeaseToken}");
}
```

- All operations must implement retry logic with exponential backoff
- Circuit breaker must protect against cascading failures
- Lease conflicts must be handled gracefully with optimistic concurrency
